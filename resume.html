Selected work

Clinical practice platform

Client build · Healthcare

Booking, clinical notes, invoicing, and payments for a live UK clinic, handling special-category health data under UK GDPR Article 9. One NestJS API behind an admin web app, a practitioner view, a client portal, and a React Native mobile app, all driven from a single OpenAPI contract so the clients cannot drift from the server.

  • Safety rules enforced as database constraints rather than application checks: no double-booked room or practitioner, no overpaid invoice, no twice-billed session, no editable issued invoice.
  • Money stored as whole pence, so the rounding error never happens.
  • Argon2id hashing, short-lived access tokens with rotating refresh tokens and replay detection, mandatory app-based two-factor for staff, per-record encryption on clinical notes, and a log redaction allowlist.
  • CI fails the build on any new high-severity dependency advisory, with each accepted exception written down alongside the condition that clears it.

Counterpart

Product · AI simulation

A conversation-rehearsal platform where professionals practice hard conversations against an AI counterpart. The design decision that makes it work: a deterministic engine owns every outcome, and the language model supplies wording only. Per-turn changes to trust and agitation are clamped, so a trainee cannot prompt-inject a passing grade, and facts the counterpart is withholding never enter the model context until the engine unlocks them. That makes the debrief auditable.

  • Personas are pure YAML config, so a new scenario or a whole new field is a data file rather than a code change. Five verticals run on one engine.
  • Runs fully local against LM Studio, which is the privacy argument for clinical and regulated buyers.
  • Test suite covers the integrity property directly, not just the happy path.
  • The engine is readable. The browser port that drives the live demo is open source: counterpart-engine.js. The clamps and the disclosure gates are the first thing in the file.

How I work

AI-native, not AI-dependent. I treat the model as a fast junior who needs supervision, not an oracle. It drafts, I read every line, and I close what it quietly gets wrong. Hiring someone who works with AI is not the risk. Hiring someone who works with AI and does not read the output is.

In practice that means the same set of checks runs before anything ships: secrets stay server-side and scoped, authorization is enforced at the data layer where the client cannot talk its way past it, endpoints carry rate limits and cost ceilings, queries are parameterized, dependencies are pinned and audited in CI, and sessions expire. Most of these are the failure modes that generated code produces by default.

On private work. The clinical platform and the client builds are described here at the capability level. The source stays private. A deeper walkthrough happens under an NDA.
