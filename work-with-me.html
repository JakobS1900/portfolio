02 · The red-team, specifically

Three questions, answered with evidence.

This is the deep version of items 13 and 14 below, and it is the work almost nobody else is selling with a public tool behind it.

Q1

Can user text move the number?

I run your scorer against a corpus of known injection payloads across seven families. Every probe is measured against a neutral control string of exactly the same character length, because appending anything at all nudges a scorer that reacts to length. Only the excess over that control counts. Without the control this test flags healthy systems and is worthless, which is why most informal versions of it are.

Q2

What is the model actually allowed to do?

Every tool, function and integration the model can reach, and what each one can read, write, delete or spend. The common finding is not an exotic jailbreak. It is a tool that was scoped for a trusted caller and then wired to a model that takes instructions from strangers.

Q3

What happens to what it returns?

Model output rendered as HTML, passed to a shell, used as a database identifier, or trusted as a routing decision. This is the 2026 version of an injection bug and it is consistently the least-defended part of an LLM feature.

OUT

What you keep

A written report with every payload that moved the score and by how much, the tool-authority map, and a regression harness wired into your test suite so a future change that reopens the hole fails CI instead of shipping. That harness is yours, it is MIT, and it works after I am gone.

What this cannot tell you. The harness compares against a fixed corpus, so a clean run is a statement about those payloads and not proof your feature is unbudgeable. It has a documented false-negative mode: a scorer that penalises off-topic padding can mask a real injection, and there is a worked example in the readme of a target that is genuinely injectable and gets a clean result. It handles one turn, not a conversation. I would rather you read that before hiring me than discover it afterwards.
03 · What gets checked

The whole checklist, published.

This is the scope of the Production Readiness Review. Most reviews keep the checklist private so the scope can move after you pay. Mine is here. Fourteen items, each scored with a written justification, whether it passes or not.

01

Authentication

Password hashing, session lifetime, refresh handling, lockout on repeated failure, second factor where it matters.

02

Authorization, IDOR and tenant isolation

Whether a valid login can reach a record it does not own by changing a number in a URL, and whether one customer can see another customer's data.

03

Secrets and key handling

Where keys live, what scope they carry, whether any of them reached a place the browser can read. I check the built bundle, not just the source.

04

Injection and SSRF

Query construction, template rendering, and anywhere the server can be talked into fetching a URL an attacker chose.

05

File upload handling

Type checked by real file signature rather than filename, size ceilings, storage location, and whether an upload can ever be served back as executable.

06

Rate limiting and abuse

What one determined script costs you, on both the bill and the availability side. Cost ceilings on anything that fans out to a paid API.

07

Dependencies and supply chain

Known advisories, pinning, install scripts, and whether anything in the tree is unmaintained enough to be a future problem.

08

Client bundle exposure and API over-fetch

What the frontend is handed that it never displays. An endpoint returning the whole user row so the UI can show a name is a leak with a nice coat on.

09

Logging and PII

Whether personal data ends up in plain text in a log, and which third-party dashboard it gets shipped to on the way.

10

Backups, migrations and rollback

Whether a backup exists, whether it has ever been restored, and whether a bad deploy can be reversed without losing the last hour of customer data.

11

Error handling

What a stack trace tells a stranger, what fails open that should fail closed, and what happens when a dependency you do not control stops answering.

12

CI and deploy gates

Whether anything actually blocks a bad change from reaching production, or whether the pipeline is a formality that goes green regardless.

13

Prompt-injection surface and tool authority

If user text reaches a model: whether that text can move a score or a decision, and exactly what the model is allowed to call, write or spend on its own.

14

LLM output handling

What you do with what the model returns. Model output rendered as HTML, passed to a shell, or trusted as a database identifier is the 2026 version of an injection bug.

04 · How findings are graded

Severity, in writing, before you hire me.

Severity is exploitability multiplied by blast radius. Publishing the rubric is the point: it is what stops me inflating a report, and it is what the no-findings refund is measured against.

CRIT

Critical

Reachable by an unauthenticated stranger, and it exposes or destroys data across every account. Live secret in the client bundle. Public endpoint that returns any user's records. Fix before the next deploy.

HIGH

High

Needs a valid login or a specific condition, then crosses a trust boundary. A logged-in user reaching another tenant's records. Unbounded spend on a paid API. Fix this sprint.

MED

Medium

Real, with a precondition or a limited blast radius. PII in logs, a known advisory in a dependency you actually call, a missing rate limit on a cheap endpoint. Fix this quarter.

LOW

Low

Hardening and hygiene. Worth doing, not worth waking anyone up for. Grouped in the report rather than itemized, so the list stays honest about what actually matters.

Why the free-if-clean offer is safe to make. It sounds like it creates an incentive to inflate. It does the opposite, because the rubric above is public and every finding has to carry a reproduction path a second engineer could follow. If I grade something Medium that is plainly Low, you can see it. I also publish the known false negative in my own open-source tool rather than quietly hoping nobody notices, which is the same instinct pointed at my own work.
